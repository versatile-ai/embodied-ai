# GPT + π0.5 抓取失败：根因研究

日期：2026-09-18。范围：源码、在线容器文件、旧实验日志和离线物理对照。
没有修改在线推理服务、权重或控制器，没有启动新的正式实验。

## 结论

**首要问题不是“已经证明 π0.5 模型不行”，而是我们的推理适配配置错误。**
ARX X5 权重被套用了标准 Aloha 的关节符号及夹爪转换；同时仿真端的夹爪
滞回和旧限速进一步放大了错误。环境能完成手工选点的真实接触抓取，但并不等价
于作者训练/评测环境；转换后的模型数值等价性也尚未充分验证。

之前将“能加载、输出有限且 shape 正确”称为“转换和部署全部验证通过”过于宽泛。
那不能证明训练与推理数据契约相同，更不能证明策略有效。此前检查漏掉了这个
关键配置差异，导致故障被误认为主要是速度/碰撞问题。

## 1. 已确认的关键配置错误

作者 GPT-as-Policy 固定版本：`8f3d362b077d8efb77e2a7274d5b2c20e2243846`。
其 [checkpoint.py](https://github.com/anonymous-report-421/GPT-as-Policy/blob/8f3d362b077d8efb77e2a7274d5b2c20e2243846/hybrid_rollout/robodojo/pi05_server/checkpoint.py)
按配置 `pi05_base_aloha_full_sim_arx-x5_seed_0` 构建数据变换。

作者依赖的 XPolicyLab `432f82b1758c5b1202e42a3dfe014546dbc50871` 中，
[配置类及 seed0 配置](https://github.com/XPolicyLab/XPolicyLab/blob/432f82b1758c5b1202e42a3dfe014546dbc50871/policy/Pi_05/openpi/src/openpi/training/config.py)
实际取值为：

| 数据契约 | 作者配置 | 192 在线部署构建方式 |
| --- | --- | --- |
| `adapt_to_pi` | **False** | **True**（generic openpi 默认值） |
| `use_delta_joint_actions` | True | True |
| normalizer | arx_x5_sim | arx_x5_sim |

**不能把 delta 也关闭**：关节在模型内部使用相对当前状态的增量，输出管线再还原为
绝对关节目标。错误是套用 Aloha 机器人空间适配，不是使用 delta 本身。

192 `/data/pi05_hybrid/scripts/pi05_service.py` 的 `build_policy()` 创建
`LeRobotAlohaDataConfig` 时没有显式传入这两个开关。本轮直接读取部署容器可见文件，
确认其 `config.py` 默认 `adapt_to_pi=True`。

### 错误如何产生

1. 输入状态的左右肩肘（14维数组索引 1、2、8、9）被取反。
2. 归一化夹爪输入被误当作另一种机械夹爪机构，经过角度转换。
3. 网络输出还原后，肩肘目标再次按 Aloha 约定取反，送往没有采用该约定的 X5。
4. 输出夹爪也经过错误换算，然后仿真端再做 0.2/0.8 滞回。

两端都有符号转换并不意味着错误抵消：网络和训练统计量不是任意坐标变换下不变的。
训练看到的肩肘状态主要为正；推理送入负值，输出又被反向执行。

远端 `aloha_policy.py` 的输出夹爪公式为：

`g_out = (g_model + 0.5476 + 0.6213) / (1.4910 + 0.6213)`

因此 ARX 的关闭值 0 被换成 **0.553378**，打开值 1 被换成 **1.026795**。
我们的夹爪控制要求 `<=0.2` 才闭合、`>=0.8` 才打开，中间维持原状态。
一旦打开，来自 π0.5 的“关闭”便可能永远无法触发闭爪。

输入端同样错误：本地初始夹爪状态 `0.185185` 被换成 **-0.627194**，而远端
normalizer 中夹爪 state/action 的 q01≈0、q99=.9998。这是明确的数据契约偏移。

## 2. 失败轨迹的证据

旧实验：`author_hybrid_20260917_225148/030fd4325941`，最终 271 步、0 瓶入桶。

- 保存了 31 次原始 π0.5 预测，合计 **3100 个夹爪输出值**。
- 原始夹爪输出范围 **[0.551671, 1.029461]**。
- `<=0.2` 的输出数量 **0**，不是偶然某次没有闭合。
- 首段左肩目标范围约 **[-1.461843, -0.000815] rad**。
- 前三段测得夹爪开度约 .184–.186，GPT 日志已注意到指令与实际开度不一致。

这与上述错误转换的方向和数值一致。不能只用模型输出的形状/有限性检测发现此类错误。

## 3. 单变量离线物理对照

取第 0000 段 `pi_raw_response.json` 的同一条 H50 预测，夹爪仅截到 [0,1]。
从相同 layout0 和初始状态开始，逐步执行50步，再保持最后目标150步（6秒）。
使用当前 MuJoCo 控制配置：ARM_CTRL_STEP=.05，CTRL_SMOOTH=.85，1000Hz物理。
**碰撞全程开启，吸附关闭，驱动力和几何不变**。

| 对照 | 最终最大手臂误差 |
| --- | ---: |
| 原始返回动作 | **0.958062 rad** |
| 仅撤销索引1、2、8、9的符号反转 | **0.004121 rad** |

同一最终左肩目标从 -1.317563 改为 +1.317563，后者实际到达 +1.321684。
这说明当前严重的撞桌/跟踪阻塞有很强的输出坐标适配因果证据，不能归咎于
“MuJoCo 碰撞坏了，所以只能关闭碰撞”。

**边界**：这是输出侧的诊断消融，不是完整修复；输入状态仍来自旧错误管线，
也没有重新执行模型推理。生产修复应从构建配置关闭错误适配，再做匹配输入的验证，
不能只在返回结果里粗暴翻转关节符号。

## 4. 环境和控制层仍有差异

| 项目 | 作者原生实验 | 当前复现 | 影响/状态 |
| --- | --- | --- | --- |
| 物理环境 | Isaac Sim / RoboDojo | MuJoCo，部分简化物体 | 视觉、接触分布不同，剩余影响未量化 |
| 初始夹爪 | joint7/8=.044，张开 | q=0，归一化约.185 | 初始观察不一致 |
| 夹爪执行 | 连续开度 | 0.2/0.8滞回 | 中间值不能忠实执行 |
| 夹爪反馈 | 最近控制开度命令 | 实测开度 | 夹住物体时尤其不同 |
| 手臂驱动 | stiffness4400/damping40 | 运行时 kp1000，kd=max(80,2√(kp·m0))；XML 的100/10会被覆盖 | 动态不同；不能直接照抄增益而不验稳定性 |
| 历史关节目标速率 | 原生控制 | 曾限制为.595rad/s有效目标推进 | 已确认造成时序积压，局部修复已完成 |
| GPT纠偏控制 | 作者数值IK/edit插值 | 本地迭代IK，部分插值不同 | 同一纠偏指令不保证相同实行动作 |
| 权重执行 | 原生JAX | 转换权重＋PyTorch/昇腾 | 没有同输入同噪声逐步数值对齐证明 |

作者原生驱动/初始姿态依据：
[RoboDojo x5.py](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/ee67a1468510da7624a089164402359f2afc72c8/env/robot_manager/robot_config/x5.py)。
其他控制契约及源码链接见 `author_control_comparison_20260917.md`；该旧文档中
“未知作者驱动参数”和“.028为当前全局限速”已被后续核查更新，不应继续当作现状。

## 5. 为什么 GPT 没有救回来

旧实验完成了30次审核：14次 student、16次 eef纠偏，不是“完全没调用GPT”。
前3次审核仍放行了12/15/15步，虽然日志已经指出关节滞后、开度不变。
第4次才明确认定后续目标会降到桌面以下并接管。

这说明审核在早期把异常解释为准备动作/不确定，而非立即判定控制契约故障。
后续短段纠偏仍夹杂错误学生动作，并且受到本地执行限制。不能期望高层GPT自动
修复底层输入输出坐标变换错误；也不能将一次逐阶段人工式GPT选点成功等同于
混合模式已通过。

本轮前已完成直接选点抓取：瓶子抬高21.6cm、保持3秒、75帧双指接触。
它证明基础接触抓取可用，不证明完整视觉策略泛化或作者环境等价。

## 6. 建议的最小修复与验证顺序（本轮未实施）

1. 明确设置 `adapt_to_pi=False`、保留 `use_delta_joint_actions=True`，保存旧服务
   配置/哈希以便回滚；不要换权重、调相机、改碰撞同时进行。
2. 在独立验证进程中，用同一观察与同一采样噪声比较旧/新输入输出变换，检查肩肘
   方向、夹爪0/1、delta还原。固定噪声须验证API支持，不能仅宣称设置了seed。
3. 将夹爪连续执行、初始张开和命令态/实测态反馈分项对齐并回归；记录改变的控制契约。
4. 先做不带GPT的短 π0.5 接近/抓取验证，量化实际关节误差、碰撞、指缝和瓶子高度。
5. 单瓶闭环通过后，再加入GPT审核，最后才执行三局正式实验。
6. 若仍失败，再做JAX/PyTorch同输入同噪声比较，以及摄像机/外观/物理参数对照。
