# 本地与 192 仿真速度对照（2026-09-17）

## 方法

两端运行同一份 `simulation/mujoco/bench_render.py`。独立瓶子场景 layout 0，原始相机标定，MuJoCo 3.3.7、三路 640×480、4096 阴影贴图、1,074,888 网格三角面。一次预热后测六个控制步，包含物理、三路渲染、PNG 编码和文件写入；不含 HTTP、模型推理、每批暂停或最终 MP4 编码。录像临时目录由脚本清理，不修改直播会话。

服务源码、XML、布局 SHA256 在两端一致：

- simsvc.py: `70fe7db0cf5870ec98ef9e11dcb831214a4ac4fe5ea95a42b87d644bcb9689aa`
- XML: `3fee1917c309edd29fa37234425201e76a1e52b7c59aabcb1f69cfb165352331`
- layout: `9f8e9a232e6e97cc0d1f6d8bec994cbf2d6357b1d0fcad54ca058b791d505b62`

## 结果

| 指标 | 本地 Windows | 192 Linux ARM64 |
|---|---|---|
| 实际 GL 渲染器 | Intel Arc 130T GPU (16GB)，驱动报告名称 | llvmpipe (LLVM 15.0.7, 128 bits)，CPU |
| Python | 3.12.11 | 3.11.15 |
| 场景加载及初次捕获 | 3.646 / 3.672 秒 | 11.542 秒 |
| 每步平均 | 0.4937 / 0.4897 秒，两次独立进程 | 4.6999 秒 |
| 每步中位数 | 0.4903 / 0.4888 秒 | 4.6948 秒 |
| 进程峰值驻留内存 | 1744.4 / 1743.6 MiB | 1699.5 MiB |

本地样本：`[0.4916, 0.4890, 0.5016, 0.4864, 0.5047, 0.4886]` 和 `[0.4936, 0.4967, 0.4900, 0.4869, 0.4876, 0.4834]` 秒。

服务器样本：`[4.6897, 4.6998, 4.7311, 4.7152, 4.6839, 4.6800]` 秒。

本地完整控制步约快 9.6 倍。仅将这段耗时乘以 700，本地约 5.7 分钟、服务器约 54.8 分钟；这不是完整策略局的实测耗时。峰值内存包括初始化，不包括独立显存，且仅适用于本次瓶子场景，不能推广到分类场景。

## 连接与边界

补测本地经 SSH 调用远端推理时，连接出现 WinError 10054 / SSH Connection reset，8763、8642 转发随后断开。重连跳板 `159.138.11.11:22` 也超时。因此本轮没有获得有效的本地到远端推理端到端耗时，不能将仿真 9.6 倍提速等同于整局策略的提速。

本轮未迁移部署、未改变正式画质或物理参数、未启动正式实验。测速脚本已通过 Python 只读审查及格式检查。

建议恢复网络后采用“本地物理与 GPU 渲染 + 192 π0.5 推理”做短程闭环测速，再决定正式部署；仍需计入图像上传、推理及录像耗时。
